# Ember

毎日ひとつだけやる、を積み上げるための記録アプリ（PWA）。

## 概要

- 登録したタスクのうち**どれか1つ**をやれば、その日は達成。全部やる必要はない
- 週（日〜土）単位では、**毎日つなぎ、全タスクを1回以上**やる。満たした週はシールド +1、満たせなかった週はシールド −1
- 連続記録は**アプリ全体で1本だけ**。シールドがない週に未達になると、翌週の日曜から0日に戻る

---

## 仕様

### 記録

| 項目 | 仕様 | 補足 |
|---|---|---|
| 達成の条件 | 登録タスクの**どれか1つ以上**を実行 | 全部やる必要はない |
| 記録の粒度 | やった / やらない のみ | 量も所要時間も持たない。達成判定に迷う余地をなくすため |
| 記録操作 | タスクの**行**を500ms長押し | 丸だけでなく行のどこでもよい。もう一度長押しで取り消す |
| 達成後 | 他のタスクも押せるまま | 連続日数は増えないが、週の必須タスクの消化になる |
| 1日の区切り | 午前4時 | 深夜0時をまたいでも前日分として記録される。設定で変更可 |
| 遡及編集 | 任意の過去日を編集できる | カレンダーのマスをタップする。その週に必須だったアーカイブ済みタスクも直せる。タスクを登録した日より前の日には、そのタスクは記録できない |

### 連続記録

| 項目 | 仕様 | 補足 |
|---|---|---|
| 単位 | アプリ全体で1本 | タスクを何個登録しても記録は1本しかない |
| 日数 | 達成した日ごとに+1 | やらなかった日は+0。週の途中では途切れない |
| 算出方法 | 日々の記録から毎回計算し直す | 値として保存しないので、過去日を編集しても矛盾しない |
| 今日が未達のとき | 空白日に数えない | まだ1日が終わっていないため |
| リセット | 週の判定で未達・シールド0枚のとき | その週は丸ごと無効になり、翌週の日曜から0日で数え直す |
| 連続0日の表示 | 他の未達日と同じ | 励ましも謝罪も、特別な文言は出さない |
| 自己ベスト | 記録から導出する | 達成した日に表示する。リセットされた週の途中で到達した日数も含める |

### 週の判定とシールド

| 項目 | 仕様 | 補足 |
|---|---|---|
| 週 | 日曜〜土曜 | カレンダーの1行がそのまま1週。午前4時区切りも同じ |
| 達成した週 | 毎日達成し、かつ必須タスクを全部1回以上 | 土曜が終わった時点で判定する |
| 獲得 | 達成した週ごとに +1枚 | 週末に確定する。週の途中はホームに見込みを出す |
| 消費 | 達成しなかった週に −1枚 | 空白日が何日あっても1枚。タスク未達だけの週も1枚 |
| 手持ちがないとき | 連続をリセット | 救済はない。未達の週が続けば順に使い切り、尽きた週でリセット |
| 必須タスク | 判定開始日までに登録していたタスク | 週の途中で追加したタスクは翌週から。週の途中でアーカイブしたタスクは翌週から外れる（その週はまだ必須）。日曜にアーカイブすればその週から外れる |
| 必須タスクがない週 | 空白日がなければ判定しない | 登録前の週を埋めてシールドを稼げないように、タスクを入れ替えた週を罰しないように |
| 最初の週 | 最初にタスクを登録した日から土曜までで判定 | 登録した日も空白日に数える。登録より前の日は数えず、記録もできない |
| 巻き戻し | 過去日を直せば週の結果も変わる | シールドも導出値なので、自動的に整合する |

### 画面とデータ

| 項目 | 仕様 | 補足 |
|---|---|---|
| 画面 | ホームと設定の2タブ | カレンダーはホームに含め、画面を跨がせない |
| ホーム | 達成した日だけ数字を大きく出す | 未達の日は行動を促す表示に切り替わる |
| カレンダー | 月ごとのカレンダー（日曜始まり） | はみ出した週は前後の月の日付を薄く出す。遡れるのは使い始めた月（または記録のある最も古い月）まで |
| 週の結果 | カレンダーの右端の列に `+1` / `−1` / `×` | 獲得 / 消費 / リセット。今週はまだ空欄 |
| 消化数 | 達成日のマスの右上にバッジで出す | 記録は「やった / やらない」のまま。数は振り返り用の情報として出すだけ |
| 今週の回数 | タスクの行に「今週 2 回」と出す | 今週の判定に入るのにまだ0回のタスクだけ朱色にする |
| 通算回数 | 設定画面のタスク一覧に「通算 129 回」と出す | そのタスクを何日実行したかの合計 |
| 外観 | システム追従 / ライト / ダーク | 連続日数に応じてアクセント色が変化する |
| 保存先 | localStorage の `ember.v1` | 端末内のみ。外部への送信は一切しない |
| バックアップ | 手動でJSONを書き出し / 復元 | iOSがデータを削除することがあるため、定期的に必要 |
| タスク削除 | アーカイブされるだけ | 過去の記録と連続日数は残る。週の途中でアーカイブしたものは、ホームに「（今週まで）」を付けて週末まで残す |

設計の意図と全ルールは [docs/spec.md](docs/spec.md)。

## 構成

```
ember/
├── index.html                    アプリ本体（HTML / CSS / JS すべて）
├── manifest.json                 ホーム画面追加時の名前・アイコン・全画面設定
├── sw.js                         オフライン用のサービスワーカー
├── robots.txt                    検索エンジン避け
├── .nojekyll                     Jekyll 処理の無効化（空ファイル。消さない）
├── .gitignore
├── README.md
├── assets/
│   ├── icon-192.png              アイコン
│   └── icon-512.png
├── docs/
│   ├── spec.md                   仕様書
│   ├── design-directions.html    デザイン方向性の検討（4案）
│   ├── icon-options.html         ナビアイコンの候補
│   ├── app-icon-options.html     アプリアイコンの候補
│   └── icon-options/             アイコン候補の画像（12枚）
└── tests/
    ├── test.mjs                  272件のテスト
    └── package.json
```

ルート直下は、置き場所が仕様で決まっているファイルだけです。`index.html` `robots.txt` `.nojekyll` はサイトルートに必要で、`sw.js` もサブフォルダに置くとサービスワーカーの制御範囲がそのフォルダ配下に限定されるため動かせません。

---

## ローカルで動かす

`index.html` をブラウザで直接開けば動きます。ただし `file://` ではサービスワーカーが登録されないため、オフライン動作は確認できません。

```bash
python3 -m http.server 8000
```

`http://localhost:8000` を開きます。同じWi-Fiなら `http://<PCのIPアドレス>:8000` でスマートフォンからも見られますが、HTTPSではないためホーム画面に追加してもPWAとしては動きません（動作確認用）。

---

## テストを走らせる

```bash
cd tests
npm install
npm test
```

配信される `index.html` を jsdom で読み込んで検証します。モックではないので、HTMLを壊せば落ちます。

連続日数の計算、週の判定とシールドの獲得・消費、週に必須のタスク、午前4時の日付境界、過去日の巻き戻し、行の長押し、今週の回数、テーマ切り替え、連続日数に連動する色など272件。ロジックに手を入れたら必ず走らせてください。
