# Ember 仕様書（α版）

名前は「熾火」から。炎を大きくすることではなく、火種を絶やさないことだけを目的とする。

---

## 1. このアプリが解決すること

**課題**: 仕事が忙しく、筋トレが続かない。週2回などの目標にすると「やらない日」が生まれ、そこから崩壊する。

**過去の失敗（Streaks）の原因**:

- タスクごとに継続記録が分かれていて、1つでも×が付くと全体のやる気が消える
- 継続回数・日時がタスク単位なので「続いている感」が育たない
- 全部やる前提がプレッシャーになる

**この設計の背骨**:

> **ストリークはアプリ全体で1本だけ。タスクは評価対象ではなく、その1本を埋めるための手段にすぎない。**

これがStreaksとの決定的な差分。タスクを何個登録しても、成績表は1本しか存在しない。

**もう1つの背骨**:

> **毎日やる。ただし「今日の最低ライン」を極端に下げる。**

トイレに行くついでのスクワット10回で今日は達成。強度に優劣は付けない。続けられるようになれば回数は自然に増える、という立場を取る。

**3つ目の背骨（週次ルール）**:

> **日は1つでいい。ただし週に1回は全タスクを一巡する。**

毎日の最低ラインは下げたままにする。その代わり、楽なタスクだけで毎日をつなぎ、懸垂を永遠にやらない、という抜け道を週単位でふさぐ。タスクごとに連続記録を持たせるのではなく、週の判定の結果は**1本しかない連続記録とシールド**にだけ効く。

## 2. 中核ルール

| 項目 | ルール |
|---|---|
| 達成の定義 | 登録タスクのうち **どれか1つ以上** を実行 |
| 1日の区切り | **午前4時**（設定で変更可。深夜帰宅後の実施を前日分として扱う） |
| 記録の粒度 | やった / やらない のみ。回数・時間・重量は記録しない |
| 記録操作 | タスクの**行**を500ms長押し（行が左から染まり、丸のリングも同時に回る） |
| 達成後 | 他のタスクも押せるまま。連続日数は増えないが、週の必須タスクの消化になる |
| 遡及編集 | **任意の過去日を編集可能**（カレンダーのマスをタップ） |
| 連続日数 | 達成した日ごとに+1。やらなかった日は+0で、**週の途中では途切れない** |
| 週 | **日曜〜土曜**（カレンダーの1行と同じ）。区切りは日と同じく午前4時 |
| 週の達成 | 判定開始日から土曜まで**毎日達成**し、かつ**必須タスクを全部1回以上**実行 |
| シールド獲得 | 達成した週ごとに**1枚**。土曜が終わった時点で確定する。保有上限なし |
| シールド消費 | 達成しなかった週に**1枚**消費して連続を維持（空白日が何日あっても1枚） |
| リセット | 達成しなかった週に手持ちが0枚なら、**その週は丸ごと無効**になり翌週の日曜から0日 |
| 使い始めた日 | 最初にタスクを登録した日（登録した日のうちにアーカイブしたタスクは打ち間違いとみなし、記録の有無にかかわらず除く。記録で判断すると、記録の足し引きで起点が動くため）。最初の週はこの日から土曜までで判定し、この日も空白日に数える。記録によって動かないので、あとから記録を足して結果が悪くなることはない |
| 必須タスク | 判定開始日（通常は日曜、最初の週だけは使い始めた日）までに登録したタスク。週の途中でアーカイブしたタスクは、その週はまだ必須で翌週から外れる。判定開始日（日曜）にアーカイブしたものは、その週から外れる |
| 必須タスクがない週 | 空白日がなければ**判定しない**（+1も−1もしない）。空白日があれば通常どおり −1 かリセット |
| 自己ベスト | 過去最高連続日数を記録から導出し、達成日に表示。リセットされた週の途中で到達した日数も含める（そのとき画面に出ていた数字のため） |
| タスク削除 | 物理削除せず**アーカイブ**。過去の記録は残る。その週の判定にはまだ入るので、ホームには「（今週まで）」を付けて週末まで残す |

### 設計上の重要な帰結

**連続日数もシールドも保存しない。毎回、日々の達成記録から計算し直す（導出値）。**

これにより、過去日を後から編集しても矛盾が起きない。シールドで守った週の空白日を後から「やってた」に修正すれば、その週は獲得の週に変わり、シールドの収支も自動的に整合する。

## 3. 週の判定とシールド

PWAはバックグラウンドで動けないため、週の判定は保存せず、**開くたびに使い始めた週から順に計算し直す**。

1. 使い始めた週（最初にタスクを登録した週）から、終わった週を古い順に1つずつ判定する
2. 毎日達成し、必須タスクを全部1回以上やった週は **+1枚**
3. そうでない週は、手持ちがあれば **−1枚** で連続を維持する
4. 手持ちがなければ連続を0に戻す（その週の達成日も含めて無効。翌週の日曜から数え直す）。ただし自己ベストには、その週の途中で到達した日数も含める
5. 今週はまだ判定しない。ホームに見込みだけを出す

**必須タスクが1つもない週**（タスクを登録する前の週を後から記録した、週の途中でタスクを全部入れ替えた、など）は、空白日がなければ判定しない。+1にすると登録前の週を埋めてシールドを稼げてしまい、−1にするとタスクを入れ替えただけの週が罰せられるため。

**救済はしない。** 未達の週が手持ち枚数を超えて続いても、古い週から順に1枚ずつ使い切り、尽きた週でリセットする。旧仕様の「埋め切れないなら消費しない」は、甘えてやらなくなるため撤去した。

**週の途中で1日欠けると、その週の −1 はその時点で確定する。** 残りの日に全タスクをやっても週の結果は変わらず、変わるのは連続日数の+1だけ。これは隠さずにホームに出す（§4）。

### 例

| 週 | 内容 | 結果 | 手持ち |
|---|---|---|---|
| 1 | 毎日・全タスク | +1 | 1 |
| 2 | 火曜が空白 | −1（連続は維持、火曜は+0日） | 0 |
| 3 | 毎日やったが懸垂0回 | リセット（翌日曜から0日） | 0 |
| 4 | 毎日・全タスク | +1 | 1 |

## 4. 画面仕様

**ホーム**と**設定**の2タブ。カレンダーは独立させずホームに置く（1画面で完結させるため）。

### ホーム（状態で切り替わる）

**今日まだ未達のとき** — 行動を促す

```
EMBER
────────────────────────
 12 日連続      シールド 2
────────────────────────

今日やること
 スクワット10回   今週 3 回  ◯   ← 行のどこでも長押しで達成
 ストレッチ1分     今週 1 回  ◯
 懸垂             今週 0 回  ◯   ← 今週まだの必須タスクだけ朱色

8月                  2026年 ‹ ›
■■■□□■■ …
```

**今日達成したとき** — 祝う

```
            13
          日 連 続
────────────────────────
自己ベスト │ シールド │   今週
   21 日   │   2 枚   │ あと 1 タスク
```

「今週」欄は今週の見込みを5状態で出す。

| 状態 | 表示 |
|---|---|
| 欠けた日なし・未実施の必須タスクあり | `あと n タスク` |
| 欠けた日なし・必須タスクすべて済み | `+1 枚 見込み` |
| 欠けた日なし・今週の必須タスクがない | `判定なし` |
| 欠けた日あり・手持ちあり | `−1 枚 見込み` |
| 欠けた日あり・手持ちなし | `週末でリセット` |

今日はまだ終わっていないので、今日が未達でも「欠けた日」には数えない。悪い見込みも隠さない。確定している結果を伏せても、日曜の朝に驚かせるだけになる。

**連続0日のとき** — 特別扱いしない

他の未達日とまったく同じ、`0 日連続` を出すだけ。励ましも謝罪も出さない。

> 当初は「今日から また1日目」という復帰用のコピーを置いていたが、励まそうとして説教くさくなったため撤去した。**言わなくていいことを言わない**ほうが、結果として復帰しやすい。

### 記録操作（ホームのタスク行）

- 押下対象は**行そのもの**。丸は状態と進捗を出すだけで、それ単体のボタンにはしない
  - 44pxの丸1点を狙うより、行のどこでもよいほうが手元を見ずに押せる（片手・移動中を想定）
  - 進捗は**丸のリング**と**行が左から染まるフィル**の2つで同時に出す。指の位置がどこでも進捗が目に入る
- 縦スクロールは殺さない（`touch-action:pan-y`）。スクロールが始まればブラウザが `pointercancel` を投げるので長押しは中断される
- 指が10px以上動いたらスクロールの意図とみなして中断する（`pointercancel` が来ない環境の保険）
- `pointerdown` では `preventDefault` しない。行で止めるとスクロールに干渉するため、文字選択とiOSのコールアウトはCSS側で抑える
- キーボードも Enter / Space の押しっぱなしで記録する。操作を1つに揃え、行に `role="button"` を持たせた分の責任を果たす

### 今週の回数（ホームのタスク行）

- 各タスクを**今週（日曜〜今日）何日実行したか**を行に出す（`今週 2 回`）
- 週次ルールの「週1回以上」をそのまま数字で読めるようにするため。レイアウトは旧仕様の通算回数と同じ
- **今週の判定に入るのにまだ0回のタスクだけ朱色**にする。今週の途中で追加したタスク（翌週から必須）は0回でも色を付けない
- 連続日数と同じく**保存しない導出値**。過去日を編集すれば追随する
- §9「作らないもの」の回数・時間・重量とは別物。1回の中身は相変わらず記録しない

### 通算回数（設定のタスク一覧）

- 各タスクを**何日実行したか**の合計（`通算 129 回`）。旧仕様ではホームの行に出していたが、今週の回数に場所を譲った

### カレンダー（ホーム下部）

- **月ごとのカレンダー**（1日から月末まで。日曜始まりで1日を曜日の列に合わせる）
- はみ出した週は**前後の月の日付を薄く出す**。月の変わり目で記録が途切れて見えないようにするため。押せば同じように編集できる
- 塗りつぶし = 達成 / 空白 = 未達。日のマスはこの2種類だけ
- **右端に週の結果列**を1本足し、各週の結果を出す。シールドは日ではなく週に付くため、週の横に出すのが素直
  - `+1`（金で塗る）= シールドを獲得した週 / `−1`（金の枠）= シールドで守った週 / `×`（控えめ）= リセットされた週
  - 今週と、使い始めた週より前の週、必須タスクがなく空白日もなかった週（判定しない週）は空欄
  - 懸垂だけやらなかった週のように、空白日がないまま消費・リセットされる週もこの列で分かる
- 達成日は**その日消化したタスク数**をマスの右上のバッジで出す。角から少しはみ出させて、日付と重ならないようにする
  - 1日の達成条件は1個のまま。バッジは達成度ではなく**振り返るための情報**として置いている
  - 未達の日には出さない（消化数が0のため）
  - 今日の枠線はマスの内側に引く。外に出すとマス間の隙間を隣のバッジと食い合って重なるため
- マスをタップで過去日を編集できる
  - アーカイブ済みのタスクも、その週に必須だったもの・その日にまだあったもの・その日に記録があるものはシートに出す（「（アーカイブ済み）」を付ける）。アーカイブ前の週を後から直せるようにするため
  - タスクを登録した日より前の日には、そのタスクを出さない（記録させない）。使い始めた日より前は判定にも連続日数にも数えないので、記録しても意味がないため
  - どのタスクにも当てはまらない記録は「（削除されたタスク）」として出し、消せるようにする
- 月めくりは**使い始めた月（または記録のある最も古い月）から今月まで**。端に来たらボタンを無効にする（それより前の空白と、来ていない未来を見に行かせない）
- 起動時と日付が変わったときは今月に戻す
- 見出しに月を出し、その右に年と前後の月のボタンを置く

### 設定

- タスクの追加・並べ替え・アーカイブ（各タスクの通算回数も出す）
- 外観（システム追従 / ライト / ダーク）
- 1日の区切り時刻
- 記録の集計値（達成日数、保有シールド、自己ベスト、シールドで守った週）
- バックアップ / 復元

初回起動時はタスク0個の空の状態から自分で登録する。

## 5. デザイン

### ライト = Editorial

紙面のように、余白と罫線と数字だけで構成する。カードもドロップシャドウも使わず、区切りはすべて細い罫線。連続日数はセリフ体で組む。

### ダーク = Ember Glow

暗がりの中で熾火が光る。数字の背後にオーラが浮かび、達成したマスは発光する。オーラの濃さは連続日数に連動する。

### 反応する色

両テーマに共通する仕掛け。アクセント色そのものを連続日数から計算する。

| 連続 | ライト | ダーク |
|---|---|---|
| 0日 | 無彩色のグレー | くすんだ灰褐色 |
| 3日 | 明るい朱 | 琥珀 |
| 14日 | 深い朱 | 燃える橙 |
| 45日〜 | ほとんど黒に近い焦げ茶 | 白熱した淡橙 |

ライトは**深く沈み**、ダークは**明るく燃える**。方向は逆だが、どちらも「濃くなった＝積み上がった」と読める。数字を読まなくても画面の色だけで現在地が分かるのが狙い。カレンダーのマスも同じ色を使うため、30日の塊と5日の塊は見た目からして別物になる。

実装は `RAMP_LIGHT` / `RAMP_DARK` の2配列を線形補間し、`--ember` / `--ember-soft` / `--ember-glow` / `--heat` の4つのCSS変数に流し込む。

さらに、**記録した瞬間だけ画面に暖色が走る**（0.5秒）。静かな画面だからこそ、この一瞬が報酬になる。

> 検討の経緯は [design-directions.html](design-directions.html)、アイコンの候補は [app-icon-options.html](app-icon-options.html) と [icon-options.html](icon-options.html) にある。

## 6. 通知

**α版では実装しない。**

理由: PWAはローカル予約通知ができず、Web Pushにはサーバーが必要。まずアプリ本体を作り、「続かない原因が本当に忘れることなのか」を実際に使って見極めてから判断する。

必要になった場合の選択肢:

- **iOSショートカットの個人用オートメーション**（サーバー不要、5分で設定、ただし達成済みの日も鳴る）
- **Web Push**（未達時のみ通知できるが、cronを回すサーバーとVAPID鍵の実装が必要）

## 7. データモデル

localStorage のキー `ember.v1` に、この形で1件だけ保存する。

```json
{
  "version": 2,
  "settings": { "dayBoundaryHour": 4, "theme": "system" },
  "tasks": [
    { "id": "t1", "name": "スクワット10回", "order": 0, "archived": false, "createdAt": "2026-08-01" },
    { "id": "t2", "name": "ストレッチ1分",   "order": 1, "archived": true,  "createdAt": "2026-08-01", "archivedAt": "2026-08-19" }
  ],
  "logs": {
    "2026-08-20": ["t1"],
    "2026-08-21": ["t1", "t2"]
  },
  "meta": { "lastBackupAt": "2026-08-10" }
}
```

- `createdAt` / `archivedAt` は週の必須タスクを決めるための日付（午前4時区切りの「今日」）

保存データが読み込めないときは、元のデータを `ember.v1.broken` に退避してから空の状態で起動し、そのことを知らせる（次の保存で元のデータを上書きしないため）。

集計値はすべて `logs` と `tasks` から導出する。保存はしない。

- **達成日数** = 使い始めた日から今日までに、1つ以上記録のある日の数（連続日数と同じ範囲。通算回数も未来日は数えない）
- **連続日数・保有シールド・自己ベスト・週の結果** = 使い始めた週から順に週を判定して求める（§3）
  - 週 W（日曜）の判定開始日 `from` = max(W, 使い始めた日)。使い始めた日 = 最初の `createdAt`（登録した日のうちにアーカイブしたタスクは除く）
  - 必須タスク = `createdAt` が `from` 以前で、未アーカイブか `archivedAt` が `from` より後（最初の週以外は `from` = W の日曜）
  - 連続日数は達成日ごとに+1。未達の週で手持ちがなければその週の終わりに0へ戻す。今日だけは未達でも空白日に数えない

## 8. 技術構成

| 項目 | 選択 |
|---|---|
| 形態 | PWA（ホーム画面に追加してフルスクリーン起動） |
| 実装 | HTML / CSS / JavaScript の1ファイル。フレームワークなし |
| ホスティング | GitHub Pages |
| データ保存 | localStorage（端末内） |
| バックアップ | 設定画面から手動でJSONを書き出し |
| サーバー | **なし** |
| 費用 | **0円** |

### 必須の実装

初回起動時に `navigator.storage.persist()` を呼ぶ。

iOSは7日間開かれなかったサイトのローカルデータを削除する。ホーム画面PWAは使用のたびにカウンタがリセットされるため毎日使う限り安全だが、**長期放置からの復帰時が最も危ない**（＝一番守りたい瞬間）。`persist()` で回避できる場合があるが保証はないため、手動バックアップは別途必要。

### 既知の制約（受け入れ済み）

- ローカル予約通知ができない
- バックグラウンド同期ができない
- 触覚フィードバックが効かない（`navigator.vibrate` がSafariで未対応）
- 長期放置でデータが消える可能性がある（バックアップで対処）
- EU圏ではスタンドアロンPWAが動かない（日本では影響なし）

## 9. α版スコープ

### 作るもの

- タスクの登録・編集・並べ替え・アーカイブ
- 行の長押しでの達成記録／取り消し
- タスクごとの今週の回数と通算回数の表示
- 連続日数の導出計算（午前4時境界）
- 週の判定（全タスク週1回以上＋毎日）によるシールドの獲得・消費とリセット
- 月ごとのカレンダー（使い始めた月までの月めくり）＋過去日の編集
- 状態で切り替わるホーム画面
- ライト／ダークと、連続日数に反応する色
- JSONのバックアップ／復元

### 作らないもの

- 通知
- 回数・時間・重量の記録
- ショップ、アイテム、レベル、実績
- クラウド同期
- 他人との共有・SNS連携

### α版で検証したいこと

1. **ストリーク1本化**で「続いている感」が出るか（Streaksとの最大の差分）
2. **極小タスク**でゼロの日を実際に潰せるか
3. **シールドの上限なし**が乱用に転ばないか
4. 通知なしで開き忘れるか
5. **週次ルール**で、楽なタスクだけに偏らなくなるか。週の途中で −1 が確定したあとに失速しないか

## 10. 保留した論点

以下はα版では意図的に単純化した。実際に使って問題が出たら着手する。

| 論点 | α版の判断 | 問題が出たときの対処 |
|---|---|---|
| シールド保有上限なし | 何もしない | 保有上限を設ける、または獲得条件を逓増させる |
| 週の途中で −1 が確定すると残りの週に賭け金がない | 何もしない | 確定後も全タスク一巡で何か得られる仕組みを検討 |
| 日曜にアーカイブして月曜に登録し直すと、そのタスクを毎週判定から外せる | 許容する（手間がかかり、自分しか使わないため） | 判定開始日のアーカイブもその週は必須にする |
| 通知なし | 実装しない | iOSショートカットで固定時刻通知 |
| データ消失リスク | 手動バックアップ | Supabase無料枠へ自動同期 |
| 強度が落ちる問題 | 気にしない | タスクごとのポイント差を導入 |
