# Ember 仕様書（α版）

名前は「熾火」から。炎を大きくすることではなく、火種を絶やさないことだけを目的とする。

---

## 1. このアプリが解決すること

**課題**: 仕事が忙しく、筋トレが続かない。週2回などの目標にすると「やらない日」が生まれ、そこから崩壊する。

**過去の失敗（Streaks）の原因**:

- タスクごとに継続記録が分かれていて、1つでも×が付くと全体のやる気が消える
- 継続回数・日時がタスク単位なので「続いている感」が育たない
- 全部やる前提がプレッシャーになる

**この設計の背骨**:

> **ストリークはアプリ全体で1本だけ。タスクは評価対象ではなく、その1本を埋めるための手段にすぎない。**

これがStreaksとの決定的な差分。タスクを何個登録しても、成績表は1本しか存在しない。

**もう1つの背骨**:

> **毎日やる。ただし「今日の最低ライン」を極端に下げる。**

トイレに行くついでのスクワット10回で今日は達成。強度に優劣は付けない。続けられるようになれば回数は自然に増える、という立場を取る。

## 2. 中核ルール

| 項目 | ルール |
|---|---|
| 達成の定義 | 登録タスクのうち **どれか1つ以上** を実行 |
| 1日の区切り | **午前4時**（設定で変更可。深夜帰宅後の実施を前日分として扱う） |
| 記録の粒度 | やった / やらない のみ。回数・時間・重量は記録しない |
| 記録操作 | 500ms長押し（リング状プログレス） |
| 達成後 | 他のタスクも押せるまま。記録は残るがポイントは増えない |
| 遡及編集 | **任意の過去日を編集可能**（カレンダーのマスをタップ） |
| ポイント | **1日1pt固定**。何個やっても同じ。累計方式（途切れても没収しない） |
| シールド | 累計7ptごとに**自動で1枚生成**。保有上限なし |
| シールド消費 | 未達のまま日付が変わったら**自動で1枚消費**し連続を維持 |
| シールド日の扱い | **連続は維持されるが、日数は増えない**（10日→シールド→10日→翌日11日） |
| 途切れた時 | **連続日数のみリセット**。ポイント・シールド・累計・カレンダー履歴は全て残る |
| 自己ベスト | 過去最高連続日数を保持し、達成日に表示 |
| タスク削除 | 物理削除せず**アーカイブ**。一覧から消えるが過去の記録は残る |

### 設計上の重要な帰結

**連続日数は保存しない。毎回、日々の達成記録から計算し直す（導出値）。**

これにより、過去日を後から編集しても矛盾が起きない。シールドで守った日を後から「やってた」に修正すれば、シールドは自動的に返却される。

## 3. シールドの自動消費（PWA固有の注意）

PWAはバックグラウンドで動けないため、シールド消費は**アプリを開いたタイミングで遡って処理**する。

1. 昨日から遡り、未達が連続している区間を数える
2. 手持ちのシールドで全部埋め切れるなら消費して連続を維持する
3. 埋め切れないなら**何も消費しない**

3番目が重要。未達日数が残シールド枚数を上回っている場合（＝どうやっても連続が切れることが確定している場合）にシールドを使うと、長期放置から復帰したときに貯めた分が無駄に全部溶ける。

## 4. 画面仕様

**ホーム**と**設定**の2タブ。カレンダーは独立させずホームに置く（1画面で完結させるため）。

### ホーム（状態で切り替わる）

**今日まだ未達のとき** — 行動を促す

```
EMBER
────────────────────────
 12 日連続      シールド 2
────────────────────────

今日やること
 スクワット10回          ◯   ← 長押しで達成
 ストレッチ1分           ◯
 懸垂                    ◯

8月                  2026年 ‹ ›
■■■□□■■ …
```

**今日達成したとき** — 祝う

```
            13
          日 連 続
────────────────────────
自己ベスト │ シールド │ 次の1枚まで
   21 日   │   2 枚   │  あと 2 日
```

**連続0日のとき** — 特別扱いしない

他の未達日とまったく同じ、`0 日連続` を出すだけ。励ましも謝罪も出さない。

> 当初は「今日から また1日目」という復帰用のコピーを置いていたが、励まそうとして説教くさくなったため撤去した。**言わなくていいことを言わない**ほうが、結果として復帰しやすい。

### カレンダー（ホーム下部）

- **月ごとのカレンダー**（1日から月末まで。日曜始まりで1日を曜日の列に合わせる）
- はみ出した週は**前後の月の日付を薄く出す**。月の変わり目で記録が途切れて見えないようにするため。押せば同じように編集できる
- 塗りつぶし = 達成 / 枠のみ = シールドで維持 / 空白 = 未達
- 達成日は**その日消化したタスク数**をマスの右上のバッジで出す。角から少しはみ出させて、日付と重ならないようにする
  - 達成条件は1個のままで、ポイントも1日1pt固定。バッジは達成度ではなく**振り返るための情報**として置いている
  - シールドの日と未達の日には出さない（消化数が0のため）
- マスをタップで過去日を編集できる
- 月めくりは**記録のある最も古い月から今月まで**。端に来たらボタンを無効にする（それより前の空白と、来ていない未来を見に行かせない）
- 起動時と日付が変わったときは今月に戻す
- 見出しに月を出し、その右に年と前後の月のボタンを置く

### 設定

- タスクの追加・並べ替え・アーカイブ
- 外観（システム追従 / ライト / ダーク）
- 1日の区切り時刻
- 記録の集計値（累計ポイント、保有シールド、自己ベスト、シールド消費数）
- バックアップ / 復元

初回起動時はタスク0個の空の状態から自分で登録する。

## 5. デザイン

### ライト = Editorial

紙面のように、余白と罫線と数字だけで構成する。カードもドロップシャドウも使わず、区切りはすべて細い罫線。連続日数はセリフ体で組む。

### ダーク = Ember Glow

暗がりの中で熾火が光る。数字の背後にオーラが浮かび、達成したマスは発光する。オーラの濃さは連続日数に連動する。

### 反応する色

両テーマに共通する仕掛け。アクセント色そのものを連続日数から計算する。

| 連続 | ライト | ダーク |
|---|---|---|
| 0日 | 無彩色のグレー | くすんだ灰褐色 |
| 3日 | 明るい朱 | 琥珀 |
| 14日 | 深い朱 | 燃える橙 |
| 45日〜 | ほとんど黒に近い焦げ茶 | 白熱した淡橙 |

ライトは**深く沈み**、ダークは**明るく燃える**。方向は逆だが、どちらも「濃くなった＝積み上がった」と読める。数字を読まなくても画面の色だけで現在地が分かるのが狙い。カレンダーのマスも同じ色を使うため、30日の塊と5日の塊は見た目からして別物になる。

実装は `RAMP_LIGHT` / `RAMP_DARK` の2配列を線形補間し、`--ember` / `--ember-soft` / `--ember-glow` / `--heat` の4つのCSS変数に流し込む。

さらに、**記録した瞬間だけ画面に暖色が走る**（0.5秒）。静かな画面だからこそ、この一瞬が報酬になる。

> 検討の経緯は [design-directions.html](design-directions.html)、アイコンの候補は [app-icon-options.html](app-icon-options.html) と [icon-options.html](icon-options.html) にある。

## 6. 通知

**α版では実装しない。**

理由: PWAはローカル予約通知ができず、Web Pushにはサーバーが必要。まずアプリ本体を作り、「続かない原因が本当に忘れることなのか」を実際に使って見極めてから判断する。

必要になった場合の選択肢:

- **iOSショートカットの個人用オートメーション**（サーバー不要、5分で設定、ただし達成済みの日も鳴る）
- **Web Push**（未達時のみ通知できるが、cronを回すサーバーとVAPID鍵の実装が必要）

## 7. データモデル

localStorage のキー `ember.v1` に、この形で1件だけ保存する。

```json
{
  "version": 1,
  "settings": { "dayBoundaryHour": 4, "theme": "system" },
  "tasks": [
    { "id": "t1", "name": "スクワット10回", "order": 0, "archived": false },
    { "id": "t2", "name": "ストレッチ1分",   "order": 1, "archived": false }
  ],
  "logs": {
    "2026-08-20": ["t1"],
    "2026-08-21": ["t1", "t2"]
  },
  "shieldsConsumed": ["2026-08-14"],
  "meta": {
    "lastCheckedDate": "2026-08-21",
    "bestStreak": 21,
    "lastBackupAt": "2026-08-10"
  }
}
```

集計値はすべて `logs` から導出する。保存はしない。

- **ポイント** = `logs` のキー数（達成日数）
- **生成シールド総数** = `floor(達成日数 / 7)`
- **保有シールド** = 生成総数 − `shieldsConsumed.length`
- **連続日数** = 今日（境界考慮）から遡り、達成日なら+1、`shieldsConsumed` にあれば±0で継続、どちらでもなければ停止。**今日だけは未達でも停止しない**（まだ1日が終わっていないため）

旧バージョンのキー `tsuzukeru.v1` が残っていれば、起動時に読み込んで新キーへ移し替える。

## 8. 技術構成

| 項目 | 選択 |
|---|---|
| 形態 | PWA（ホーム画面に追加してフルスクリーン起動） |
| 実装 | HTML / CSS / JavaScript の1ファイル。フレームワークなし |
| ホスティング | GitHub Pages |
| データ保存 | localStorage（端末内） |
| バックアップ | 設定画面から手動でJSONを書き出し |
| サーバー | **なし** |
| 費用 | **0円** |

### 必須の実装

初回起動時に `navigator.storage.persist()` を呼ぶ。

iOSは7日間開かれなかったサイトのローカルデータを削除する。ホーム画面PWAは使用のたびにカウンタがリセットされるため毎日使う限り安全だが、**長期放置からの復帰時が最も危ない**（＝一番守りたい瞬間）。`persist()` で回避できる場合があるが保証はないため、手動バックアップは別途必要。

### 既知の制約（受け入れ済み）

- ローカル予約通知ができない
- バックグラウンド同期ができない
- 触覚フィードバックが効かない（`navigator.vibrate` がSafariで未対応）
- 長期放置でデータが消える可能性がある（バックアップで対処）
- EU圏ではスタンドアロンPWAが動かない（日本では影響なし）

## 9. α版スコープ

### 作るもの

- タスクの登録・編集・並べ替え・アーカイブ
- 長押しでの達成記録／取り消し
- 連続日数の導出計算（午前4時境界）
- ポイント累計とシールドの自動生成・自動消費
- 月ごとのカレンダー（記録のある月までの月めくり）＋過去日の編集
- 状態で切り替わるホーム画面
- ライト／ダークと、連続日数に反応する色
- JSONのバックアップ／復元

### 作らないもの

- 通知
- 回数・時間・重量の記録
- ショップ、アイテム、レベル、実績
- クラウド同期
- 他人との共有・SNS連携

### α版で検証したいこと

1. **ストリーク1本化**で「続いている感」が出るか（Streaksとの最大の差分）
2. **極小タスク**でゼロの日を実際に潰せるか
3. **シールドの上限なし**が乱用に転ばないか
4. 通知なしで開き忘れるか

## 10. 保留した論点

以下はα版では意図的に単純化した。実際に使って問題が出たら着手する。

| 論点 | α版の判断 | 問題が出たときの対処 |
|---|---|---|
| シールド保有上限なし | 何もしない | 保有数に応じて価格を逓増（7pt→14pt→28pt） |
| ポイントの用途がシールドのみ | 何もしない | 実績・レベルなどの用途を追加 |
| 通知なし | 実装しない | iOSショートカットで固定時刻通知 |
| データ消失リスク | 手動バックアップ | Supabase無料枠へ自動同期 |
| 強度が落ちる問題 | 気にしない | タスクごとのポイント差を導入 |
